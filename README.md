# @kishanscaler/ssx-ui

The React half of the Scaler Design System. One system, two sub-brands (SST, SSB),
two modes (light, dark), composed independently on `<html>`:

```html
<html data-brand="ssb" data-theme="dark">
```

The token layer is **not** authored here. It is generated by `scripts/build.py` at the
repo root and copied in by `npm run sync:tokens`. This package owns components; it does
not own colour.

---

## Foundation

shadcn/ui's architecture, not its copy-paste model:

| Piece | What it is | Why |
|---|---|---|
| Radix `Slot` | `asChild` polymorphism | A link can look like a button without a duplicate `LinkButton` that then drifts |
| `class-variance-authority` | variant -> class mapping | Variants are data, so they can be listed, tested and documented |
| `tailwind-merge` | `className` conflict resolution | Makes `className` a safe escape hatch rather than a specificity race |
| Tailwind v4 | the utilities | `@theme inline` binds them to our semantic tokens, so `bg-surface` follows the toggles |
| `data-slot` | the styling hook on every element | shadcn's convention. A consumer targets `[data-slot="button"]`, never a class we might change |

Components follow shadcn's shape, not just its dependencies: a `cva` recipe plus a
`React.forwardRef` component with a `displayName` (shadcn uses a plain function with `ref` as a
prop, which only React 19 supports; we support 16.12+), compiled with the classic JSX runtime
(`React.createElement`; React 16.12 has no `react/jsx-runtime`), icons composed as
**children** rather than passed as props, a square button as a `size` rather than a
boolean, and **no per-component stylesheet**. A rule that lives in a stylesheet is
invisible from the call site and is how a component and its styling drift apart. The one
shared exception is `styles/components.css`, which holds only what Tailwind has no syntax
for (pseudo-element content, `@keyframes`, SVG `stroke-dashoffset` against `pathLength`),
inside `@layer components` so any utility, including a consumer's `className`, beats it.

The peer range is **React `^16.12.0 || ^17 || ^18 || ^19`**. Two consumers are
supported and tested: a Next.js 16 App Router site (`npm run smoke`) and a Rails monolith on
React 16.12 + webpack 4 (`npm run smoke:legacy`). How to write an atom that works on both:
`docs/05-react-architecture.md` section 6 — a complete template file to copy.

It is published as a versioned package rather than pasted in per-project, because a
design system that is copied is a design system that cannot be updated.

## Install

```bash
npm install @kishanscaler/ssx-ui
```

### 1. Styles

**If your app uses Tailwind v4** (recommended):

```css
/* app/globals.css */
@import 'tailwindcss';
@import '@kishanscaler/ssx-ui/styles.css';
```

That is all. No `@source` line: the package's stylesheet declares its own
(`@source '../components/**/*.js'`, resolved relative to the package, so it works with npm,
pnpm and monorepos).

You now also get the semantic utilities in your own markup — `bg-surface-raised`,
`text-content-secondary`, `border-border-decorative`, `text-action-danger-fg`, and so on —
and, by design, **only** those:

- Tailwind's default colour palette is removed (`--color-*: initial`), so `bg-blue-500` and
  `text-white` do not exist. A raw palette colour would not follow `data-brand` /
  `data-theme`. `transparent` and `current` still work.
- Breakpoints are ours: `xs 320`, `sm 672`, `md 1056`, `lg 1312`, `xl 1584` (px). Tailwind's
  `2xl` is removed.
- `dark:` is bound to the same rule as the tokens: `data-theme="dark"` on an ancestor, or the
  OS prefers dark and nothing pins `data-theme="light"`. Components never use it; it is for
  your own markup.

**If your app does not use Tailwind:**

```ts
import '@kishanscaler/ssx-ui/standalone.css';
```

Same tokens and components, utilities pre-compiled. No build step on your side.

**webpack 4 / webpacker (the Rails app), or anything that ignores `exports`:** import the
real file paths. These are stable and documented; they are also listed in `exports`, so
the same path works in Next.js too.

```js
import '@kishanscaler/ssx-ui/dist/ssx.standalone.css';          // everything (tokens + components)
import '@kishanscaler/ssx-ui/dist/styles/tokens.generated.css'; // tokens only
import '@kishanscaler/ssx-ui/dist/styles/fonts.css';            // Google Fonts
```

Sprockets: add `node_modules` to `config.assets.paths`, then
`*= require @kishanscaler/ssx-ui/dist/ssx.standalone`. The file is plain CSS with no `@import`.
It parses on PostCSS 7 / css-loader 3 / postcss-preset-env 6 (verified). Its browser floor
is Tailwind v4's `@layer`: Chrome 99, Safari 15.4, Firefox 97. See
`docs/05-react-architecture.md`, "CSS delivery".

### 4. Mobile setup

**The viewport tag.** Without it a phone lays the page out at about 980px and scales it
down, and none of the responsive behaviour below happens. Put it in every layout (Rails
`application.html.erb`, Next.js does it for you):

```html
<meta name="viewport" content="width=device-width, initial-scale=1" />
```

Do not add `maximum-scale=1` or `user-scalable=no`. They stop people from zooming, which
fails WCAG 1.4.4, and the system does not need them: see the next point.

**Field text on touch screens.** iOS Safari zooms into any focused field whose text is
under 16px and does not zoom back out. So on a touch device (`pointer: coarse`) every
text field is 16px at every size — Input, Textarea, NumberInput, PhoneInput, and so
everything built on them (SearchInput, DateInput, DatePicker, Combobox, Field). The
field height does not change. A mouse or trackpad keeps the desktop sizes (13 / 15 /
16px). Your own fields can use the `field-text` utility (15px, 16px on touch) or the
`pointer-coarse:` variant from `theme.css`.

**Tap targets.** On a touch device, controls smaller than 44px get an invisible hit area of
at least 44 × 44px, centred on the control (the `touch-target` utility): Button,
IconButton and ToggleButton at every size, Checkbox, Radio, Switch, the Slider handle and
rail, the Select trigger, the NumberInput steppers. The controls keep their drawn size and
nothing moves. What that means for your layout:

- Leave room. Two targets closer than 44px centre to centre share the overlap, and the one
  later in the page wins a tap between them. Wrap a Checkbox and its text in one `<label>`
  (or use Field) so the whole row is the target; in a vertical RadioGroup the hit area
  stays inside the gap between rows for this reason.
- Inside a ButtonGroup or welded ToggleButtonGroup the members' areas are their own width,
  so a tap near a seam is never ambiguous. The group scrolls sideways when it does not
  fit, which clips the area to the group's height: on touch, prefer `md` or `lg` members.
- A hit area cannot reach outside a parent with `overflow: hidden` or a scroll container.
- Select rows are 44px tall on touch (a real layout change, inside the popup only).

**Long labels.** A Button is never wider than its container. A label too long for one
line wraps, centred, and the button grows taller from its size's height (a full-width
button on a phone, typically); an inline button that fits stays one line. Icon sizes
never wrap. Heading and Text break a long unbroken word (a URL, an email) instead of
pushing the page wide.

**Sizes are rem** (decided 2026-09-24). Space, font sizes, the type roles, radii and the
control / icon / touch / container sizes are emitted in rem at a 16px base, and so are the
components' own arbitrary values. A reader who raises the browser's default font size gets a
proportionally larger system (measured: every component's boxes and text at x2.00 under a 200%
root size); at the default size nothing moved (398 stories screenshotted before and after, pixel
for pixel). Still px, on purpose: borders and hairlines (1-2px), focus rings (`ring-[3px]`),
shadows, `radius-full`, media-query breakpoints (a rem in a media query resolves against the
browser default, not the root, so it would not mean what it says), and the 16px floor inside
`field-text` (iOS zooms under 16 computed px, whatever the root size). Tokens stay authored in
px in `tokens/*.json`; `scripts/build.py` writes the rem. In your own markup, prefer the token
utilities; for an arbitrary value write rem (`w-[17.5rem]`, not `w-[280px]`). Radix offsets
(`sideOffset={8}`) are numbers in px and stay numbers.

**Breakpoints** are tokens and Tailwind's names: `xs` 320, `sm` 672, `md` 1056, `lg` 1312,
`xl` 1584. Most components are fluid and never switch. The ones that do — Heading type
roles (`sm`), Stepper, Toast and SelectableCard columns (`sm`), TopNav's menu button,
AppShell's drawer (`md`), Carousel, BottomSheet's split — are listed with their widths
in [`docs/responsive-audit.md`](docs/responsive-audit.md), "What changes at each width".

### 5. Type roles and the page gutter

**Type roles.** Text is set with a **role**, not a size: one utility sets size, line height
and tracking together from the composite `--type-*` tokens, and steps at `sm` where the role
does. Pick the role by what the text is for.

| Utility | Size (phone → `sm`+) | For |
|---|---|---|
| `type-display` · `type-h1` · `type-h2` · `type-h3` | 28→36 · 24→28 · 20→24 · 18→20 | headings (+ weight). `Heading` uses these |
| `type-body-lg` | 16→18 | a lede, once |
| `type-body` | 16 | running text. `Text` default |
| `type-body-sm` | 13 | supporting and help text, descriptions |
| `type-label` | 14 | form labels (+ weight). Field's label is still 13px `text-sm`: open decision, see `docs/responsive-audit.md` S7 |
| `type-eyebrow` | 12, 0.08em tracking, caps (+ weight) | the kicker above a title; group labels in menus and lists |
| `type-caption` | 12 | captions, meta, timestamps, **fine print** |
| `type-code` | 13→14 | code (with `font-mono`) |
| `type-hero`, `type-billboard-{sm,md,lg,xl}` | | marketing only |

Weight is part of the heading, label and eyebrow roles; the running-text roles inherit it. A
single utility after a role changes just that property and keeps the rest: `type-h2
font-medium`, `type-body text-content-secondary`. `cn()` knows the roles, so a later `type-*`
in `className` replaces an earlier `text-*` / `leading-*` / `tracking-*`.

Fine print (a disclaimer, the T&C under a fee) is `<Text size="xs">`, the caption role at 12px.
**12px is the floor**; there is no 10px text size. Make fine print quieter with
`tone="secondary"`, not smaller.

Controls with a fixed size ramp (Button, Input, Select sizes) keep the `text-sm` / `text-base` /
`text-md` scale on purpose: control text is 13 / 15 / 16px and does not step at `sm`.

**The page gutter.** `--space-gutter` is the space between the screen edge and the content on
anything that owns the page edge: **16px on a phone, 24px from `sm`**. Use `px-gutter` (also
`pl-gutter`, `-mx-gutter`, `scroll-px-gutter`, ...) on the element that touches the edge, not
inside cards. With a notch in landscape:
`pl-[max(var(--space-gutter),env(safe-area-inset-left,0px))]`. AppShell's content well, a
Banner, the Toast viewport and (on phones) the TopNav bar already sit on it. In Storybook every
story is padded by the gutter; a page-level story sets `parameters: { pageLevel: true }` to drop
the padding and show its own.

## Use

Import everything from the package root, including in a Server Component, and in a
webpack 4 app (it resolves `module` → `dist/legacy/index.js`, with dependencies already
bundled and lowered to ES2019, so Babel can keep excluding `node_modules`). The root is a
re-export-only barrel with no directive; each client atom (today: `Button`) carries its own
`"use client"`, so Next.js treats exactly those as client references.

```tsx
import { Button } from '@kishanscaler/ssx-ui';

<Button variant="primary" onClick={apply}>Apply now</Button>
<Button variant="secondary"><DownloadIcon />Download brochure</Button>
<Button variant="danger" size="sm">Withdraw application</Button>
<Button size="icon-md" aria-label="Search students"><SearchIcon /></Button>
<Button className="w-full">Apply now</Button>
<Button asChild><a href="/apply">Apply now</a></Button>
```

### Button

| Prop | Type | Default | |
|---|---|---|---|
| `variant` | `primary` · `secondary` · `tertiary` · `danger` · `neutral` | `primary` | What it **means** |
| `size` | `sm` · `md` · `lg` · `icon-sm` · `icon-md` · `icon-lg` | `md` | 32 / 40 / 48px; the `icon-*` sizes are square |
| `loading` | `boolean` | `false` | Renders a `<Spinner>`; stays focusable. `sm` / `icon-sm`: the six-dot grid; `md` / `lg` / `icon-md` / `icon-lg`: the monogram |
| `shine` | `boolean` | `false` | A specular sweep across the fill |
| `asChild` | `boolean` | `false` | Render as the child element |

Plus every native `<button>` prop.

**Five things to know, three of which are shadcn conventions:**

1. **Icons are children**, in whatever order you want them. There is no `leadingIcon` /
   `trailingIcon` prop. The button still owns their size (`[&_svg]`) and tightens its own
   padding when one is present (`has-[>svg]:px-*`). An icon that sets its own size keeps
   it — that is what `:not([class*='size-'])` is for.
2. **A square button is a size**, not a boolean: `size="icon-md"`. `aria-label` is
   required, because an icon is not an accessible name.
3. **Full width is `className="w-full"`.** Layout belongs to the parent, so there is no
   `block` prop for it.
4. `loading` uses `aria-busy` + `aria-disabled`, not the `disabled` attribute. A disabled
   button leaves the focus order; a busy one should not. The shadcn way is to compose
   `<Button disabled><Spinner />Saving</Button>` yourself; the prop exists only because
   that composition also has to get those two attributes and click suppression right.
5. **`shine` is a modifier, not a variant.** It adds nothing to the button's meaning, so it
   stacks on any variant. It belongs to delight and is refused everywhere delight would be
   wrong: on `danger`, while `loading`, while disabled, and under `prefers-reduced-motion`.
   All four refusals live in `styles/components.css` beside the rule they override — the
   component emits `data-shine` as asked and does not second-guess it, so the rule has one
   home rather than two that can disagree.

Removed on the way to this shape and not coming back as props: `pressed` (a toggle is a
different control with different semantics, so it will be its own component) and the
development-time `console.warn` invariants (they mirrored `verify_preview.py`, which gates
the HTML preview, not this package).

### The brand, kept

The parts of the HTML preview that were the system's **character** rather than its API came
across intact — only the class hooks changed, from `.ssx-btn--*` to the `data-slot` /
`data-variant` attributes shadcn already uses:

- **The shine.** A long sweep with most of the cycle spent still; a continuous one stops
  reading as a highlight and starts reading as a loading bar.
- **The loader. Small sizes use the dots loader; bigger sizes use the monogram** (decided
  2026-09-23). `<Spinner size="sm">` (16px) is six dots in a 2×3 grid, lit one after
  another round the outside, clockwise, matching the HTML `.dots`. It is the package's only
  dots loader: a pending Switch (`SwitchStatus`) renders this same Spinner rather than a
  copy; at `md` and above the brand mark draws itself — contour, then glyph,
  then filled. The root carries `data-kind="dots"` or `"monogram"`. A md/lg Button's
  loading state passes `kind="monogram"` at 16px, which is the solid silhouette inking
  upward (the HTML `.btn.is-loading`). `[data-brand='ssb']` anywhere up the tree swaps
  which mark shows.

These two are the only rules in `styles/components.css` today, and they are there because
Tailwind has no syntax for what they need: pseudo-element content, `@keyframes`, and
`stroke-dashoffset` against `pathLength`. Everything else is a utility on the component.

### DisplayBanner (marketing and announcement cards)

The promo cards on the Storyblok sites (SST, SSB) and the announcement strips in the
dashboards. **The system ships the shell** (surface, slots, layout, contrast, reflow);
**the site ships the artwork** (illustration, campaign photo, copy) through `media` /
`DisplayBannerMedia`. It is its own organism, not a Card variant.

```tsx
// Flat form: one prop per Storyblok field. Every visual axis is a string union.
<DisplayBanner
  surface="solid" tone="accent1" mediaPlacement="popout" layout="split" size="md"
  eyebrow="Referral" title="Refer a friend," titleMuted="get ₹5,000"
  description="For every friend who joins the Batch of 2027."
  primaryAction={{ label: 'Refer now', href: '/refer' }}
  secondaryAction={{ label: 'How it works', href: '/refer#faq' }}
  countdownTo="2026-09-30T23:59:00+05:30" countdownLabel="30 Sep, 11:59 PM IST"
  finePrint="T&C apply." mediaSrc="/art/gift.png"
/>

// Compound form.
<DisplayBanner surface="gradient" tone="inverse" layout="wide">
  <DisplayBannerContent>
    <DisplayBannerEyebrow>Placements</DisplayBannerEyebrow>
    <DisplayBannerTitle>Hire in <DisplayBannerTitleMuted>30 days</DisplayBannerTitleMuted></DisplayBannerTitle>
    <DisplayBannerDescription>…</DisplayBannerDescription>
    <DisplayBannerActions><Button>Post a role</Button></DisplayBannerActions>
    <DisplayBannerFinePrint>…</DisplayBannerFinePrint>
  </DisplayBannerContent>
  <DisplayBannerMedia inset><DisplayBannerPanel>92% placed</DisplayBannerPanel></DisplayBannerMedia>
</DisplayBanner>
```

| Prop | Values | Default |
|---|---|---|
| `surface` | `subtle` `solid` `gradient` `image` `glass` | `subtle` |
| `tone` | `brand` `accent1` `accent2` `neutral` `inverse` (ignored by `image`) | `brand` |
| `mediaPlacement` | `end` `start` `bottom` `background` `popout` (`image` always uses `background`) | `end` |
| `layout` | `stacked` `split` (side by side from a 36rem **container**) `wide` (from 48rem) | `split` |
| `size` | `md` (title `type-h2`) `lg` (`type-h1`, `type-display` in a 48rem container) | `md` |
| `actionAppearance` | `button` `arrow` ("Learn more" with a circled arrow) | `button` |

- **Contrast is handled by the component.** `gradient` is built from semantic tokens only:
  a linear wash from the tone's tint (`surface-brand-subtle`, `accent1-surface`, …) into
  `surface-page`. Every text role clears 4.5:1 on both stops in all four themes. `inverse`
  washes from `surface-inverse` into a 40% mix of `surface-brand-solid`; its lowest pair is
  4.84:1. On `solid` and `inverse` the content roles **and the action roles** are
  re-pointed to the fill's ink: the primary Button becomes the ink as its fill, with the
  surface colour as its label. Over a photo (`image`, or `background` media) the content
  brings its own scrim, which covers the whole content box, so text is on the scrim however
  long it runs. `glass` puts the content on a frosted panel (`surface-default` at 88%,
  4.5:1 or better over pure black and pure white art). Badges and Chips keep the page roles.
- **Popout** art breaks out of the top edge. The banner reserves the space above it
  (`--display-banner-popout`: 2.5rem at `md`, 3rem at `lg`; override it with a class such
  as `[--display-banner-popout:4rem]`), and the media frame clips only the bottom-end corner.
- **Linked.** `href` (or `asChild` with a `next/link`) makes the whole banner one link
  (ClickableCard's pattern). Nothing interactive may go inside it: the flat CTA is drawn as
  a span, and `secondaryAction` is dropped. The link's name is its text, or your `aria-label`.
- **Media** is decorative by default (`mediaAlt=""`). A direct `img`, `svg`, `video` or
  `next/image fill` child fills the frame. Add `inset` for sub-cards or a QR code.
- Server component. The marketing gradient roles (`tokens/marketing.gradient.json`) are
  not used and not shipped: they are unfinished.

### Build output

`vite build -c vite.lib.config.ts` runs twice (library mode, `preserveModules`,
`rollup-plugin-preserve-directives`, classic JSX, target ES2019, ESM **and** CJS each time):

| Directory | Read through | Dependencies |
|---|---|---|
| `dist/` | `exports` (`import` → `.js`, `require` → `.cjs`): Next.js, Vite, webpack 5, Node | external |
| `dist/legacy/` | `module` / `main`: webpack 4 and anything else that ignores `exports` | bundled into `dist/legacy/vendor/`, `react/jsx-runtime` shimmed |

Why two: webpack 4 cannot parse Radix as published (`?.`, `??`) and Radix imports
`react/jsx-runtime`, which React 16.12 lacks. Details and evidence in
`docs/05-react-architecture.md`, "Two consumers, two builds".

`"use client"` survives, first line, on exactly the files that declare it, in both formats.
`tsc -p tsconfig.build.json` writes a `.d.ts` beside each module and
`scripts/fix-dts-extensions.mjs` adds `.js` to their specifiers and writes a `.d.cts` twin.
The stylesheets are copied as source (a Tailwind consumer compiles them), and
`dist/ssx.standalone.css` is the pre-compiled one.

Gates `npm run build` runs: `scripts/check-directives.mjs` fails when a module uses a hook,
imports a client Radix package or `input-otp`, or attaches an event handler without
`"use client"`, and when the client modules differ from the manifest in
`scripts/client-manifest/` (**a new client atom goes in your batch's file there**).
`scripts/check-legacy.mjs` fails when any emitted file (vendored code included) is not
ES2019, imports `react/jsx-runtime`, is `.mjs`, or when a `package.json` entry point is
missing.

### Tests on two Reacts

`npm test` runs the suite on React 19 (`vite.config.ts`) and again on React 16.12 + React
Testing Library 12 (`vitest.react16.config.ts`). React 16 lives in its own install,
`test-env/react16/` (a `file:` devDependency, so `npm install` sets it up), because an npm
alias would leave react-dom@16 resolving React 19. Any `console.error` / `console.warn`
during a test fails it (`src/test/setup.ts`), which is how React 16-only warnings surface.

### Storybook deploy

`npm run build-storybook` writes a fully static site to `storybook-static/` (open
`index.html` through any static server). Either host works as-is:

- **Chromatic**: `npx chromatic --project-token=<token> --build-script-name=build-storybook`
  (or `--storybook-build-dir storybook-static` after building). It also gives visual diffs
  per brand/theme if each is captured as a mode.
- **Vercel**: root directory `react`, build command `npm run build-storybook`, output
  directory `storybook-static`, framework preset "Other".

The build needs `../dist/tokens.css` (the root Python build) because `prebuild-storybook`
syncs tokens; commit that file or run the root build in CI first. The Brand and Theme toolbar
globals can also be set by URL: `iframe.html?id=atoms-button--variants&globals=brand:ssb;theme:dark`.

Storybook's toolbar carries **Brand** and **Theme**. Use both. The single most expensive
lesson in this repo's history: three of four `accent1` ramp versions were reviewed hard in
light mode, and the one defect that shipped was in dark. Do not review one mode and assume
the other.

### Conventions

- **PascalCase** directories and files for components; one folder per component; a local
  `index.ts` barrel, re-exported from `src/index.ts`.
- **Co-located** stories and tests. A component you cannot see and cannot test is not done.
- **Named exports only.** A default export lets two call sites give one component two names.
- Stories are **CSF3** with `tags: ['autodocs']`. The props table is generated from the
  TSDoc on the props interface, so the docs cannot drift from the types.
- **No component stylesheet.** A component is styled entirely in utilities on the
  component itself. If you genuinely cannot express something as a utility — pseudo-element
  content, `@keyframes`, a mask — say which of the three it is and add the rule to
  `styles/components.css`, inside its `@layer components` block. Reaching for CSS otherwise
  means the component is wrong.
- **`React.forwardRef` + `displayName`, classic JSX, `import * as React`.** The template is
  `docs/05-react-architecture.md` section 6.
- **`'use client'` only where needed** (a hook, a handler we attach, a client Radix
  primitive), as line 1, and listed in your batch's `scripts/client-manifest/batch-*.mjs`. See
  `docs/05-react-architecture.md` section 5.
- **Scoped Radix packages** (`@radix-ui/react-checkbox`, ...), not the `radix-ui`
  monopackage: a library using eight primitives should not install thirty.
- No raw hex, ever. If a token does not exist for it, the token layer is what needs the
  change.

### Icons

There is no icon pack in this package, by decision (2026-09-23). Pass any svg icon as a
child; the component sizes and colours it. Use **`@phosphor-icons/react`**, the set the
design system is drawn with:

```tsx
import { DownloadSimple } from '@phosphor-icons/react';

<Button variant="secondary"><DownloadSimple />Download brochure</Button>
<Icon size="lg" label="Verified"><SealCheck weight="fill" /></Icon>
```

`lucide-react` also works in Next.js, but its CommonJS build uses syntax webpack 4 cannot
parse, so it breaks the Rails app unless that app transpiles it.

place, and tracked rather than assumed: the `registry.json` allowlist, the raw-value lint,
